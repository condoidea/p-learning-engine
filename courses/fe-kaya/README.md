# BIT RUSH 教科書順（fe-kaya）

基本情報技術者試験コース（`courses/fe`）の中身を、書籍
『令和08年 イメージ＆クレバー方式でよくわかる かやのき先生の基本情報技術者教室』の
**目次（章・節）の順に組み直した復習用コース**。本を読み進めた節を、ここで思い出して定着させる。

- 入口：`fe-kaya.html`（学習データは `le.fekaya.v1`。元の基本情報コースとは別に保存）
- **本の文章・図・問題は使わない**。参考にしたのは目次の並びと節の名前だけ。説明は自分の言葉で書く
- どの節からでも始められる（`COURSE.openAll`）。節番号は本と同じ（`no: '1-01'`）

## しくみ

1. `course.js` の `files` で、基本情報コースのデータ（問題・レッスン・カード）をそのまま読み込む
2. `data/kit.js` がユニット・レッスン・カードをいったん片付け、道具 `K` を用意する
3. `data/chNN.js`（章ごと）が、元レッスンの説明（ステップ）を**キーワードで指して借り**ながら、節＝レッスンを組み立てる
4. `data/finish.js` の `K.finish()` が、元レッスンの問題を「説明の内容がいちばん近い節」に自動で振り分ける

基本情報コース側の説明を直すと、こちらにも反映される（キーワードが見つからなくなったら `check-course` がエラーで知らせる）。

## 節（レッスン）の書き方

```js
K.chapter({ id: 'c3', name: '基礎理論', icon: '∑', color: '#38e8ff', desc: '［科目A］…', boss: { name: '…', ico: '🗿' } });

K.lesson('c3', {
  id: 'k3-01', no: '3-01', title: '基数変換', goal: '…できる',
  from: ['u1-1', 'u1-2'],          // 問題を引き継ぐ元レッスン（そのレッスンの問題がこの節にも振り分けられうる）
  steps: [
    K.R('u1-1', '先頭ステップのキーワード', '末尾ステップのキーワード'),   // 範囲で借りる
    K.S('u1-2', 'キーワード'),                                          // 1つ借りる
    K.P(K.S('u1-1', 'おまけ。'), { text: 'つなぎを直した本文' }),       // 借りて一部を書きかえる
    { t: 'say', text: '新しく書いた説明', ask: { q: '予想して', o: ['正解', '誤り1'], why: ['', 'ちがう理由'] }, reveal: '答えのあとの説明' },
    { t: 'recap', points: [ { q: '思い出すための問い', a: '**答え**' }, '__覚え方のヒント__' ] }
  ],
  card: { ana, vizFind, how: [], extra: [{ t, b }], traps: [] }   // または 'u1-1'（元カードを流用。vizFind がこの節の図にあること）
});
LE.addTo('k3-01', 'basic', [ { q: '本番形式の問題文', o: ['正解', '誤1', '誤2', '誤3'], e: '解説' } ]);
```

- キーワードは、ステップの本文（text・q・word・short・steps・pairs など）に**ちょうど1回**出る文字列。0回・2回以上はエラー
- 元レッスンの途中から借りると「次は」「最後に」などのつなぎが変になる → `K.P` で直す
- 元レッスンの `recap` は借りない（その節に合わせて新しく書く）。`K.recap(id, [番号])` で元の要点を選んでもよい
- `recap` の各要点は **`{ q, a }`（問い＋答え）**。答えはぼかされ、問いを見て思い出してからタップする（三角比で好評）。覚え方のヒントは文字列のまま
- 新しく書いた節・ステップには `/* 新規 */` とコメント
- `LE.addTo` の分野ID は `courses/fe/data/syllabus.js` の `LE.fields`（basic, algo, comp, sys, sw, hw, db, nw, sec, dev, pm, sm, audit, sysst, biz, corp, law, btrace, bsec）

## 品質のルール（必ず守る）

`docs/学習設計ノウハウ.md` と `docs/コースの作り方.md` の「教材の書き方」に従う。特に：

1. **知識を入れる前に問題を出さない**。説明 → すぐ思い出す（ask / quiz / match）→ 定着
2. **受け身の「次へ」を続けない**。`say` が2枚続いたら ask か quiz・match を入れる
3. 太字 `**…**` は**試験のために覚えること**だけ。覚え方は `__…__`、この教材での呼び方は `((…))`
4. 計算は「`steps` で例題 → `num` で自力」
5. 問題を解くのに必要な知識は、必ずその節（かそれより前の節）で教える
6. 1つの `say` は3行程度。1画面1アイデア
7. 事実は正確に（試験の公式・定義）。自信がない内容は書かない
8. 節の分量は 5〜12 ステップ。最後は `recap`
