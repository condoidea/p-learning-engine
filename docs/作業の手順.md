# 作業の手順（どのアプリにも共通）

## 始める前
- [README.md](README.md) の索引で読むものを決める。[原則.md](原則.md) は毎回。
- 古いディレクトリ `基本情報技術者試験/` は触らない（旧版・凍結）。
- 公開リポジトリなので、参考書・本から作ったデータ（`vocab/decks/private/` や database）は commit しない。

## 新しいアプリの入口 html
- `<meta charset>` の次に `<script src="shared/cloud.js?v=2"></script>`（`?e2e` `?sandbox` はクラウドに同期されない）。
- `news/news.js?v=2` を1行。ITEMS に足すのは**広めたいアプリだけ**（私用は足さない）→ [お知らせ.md](お知らせ.md)。

## 教材チェック（Node・依存なし）
```bash
node tests/check-course.js <コースID>     # 例: fe
node tests/check-mole.js
node tests/check-relativo.js [--memo]     # --memo で docs/vocab/スペイン語単語メモ.md を書き直す
node tests/check-manda.js [--forge]
node tests/check-protesto.js [--words]    # --words: 単語帳にない語の一覧
node tests/check-quien.js [--words]
node tests/check-futuro.js [--words]
node tests/check-yuki.js
node tests/check-vocab-deck.js <デッキ> [--verbs]
```
エンジンを変えたら全コースで通す。台本の文字列の中に生の改行（構文エラー）が1つあると、そのアプリのチェックは全部止まる。

## ブラウザの通しテスト
- エンジンのコース：`<コース>.html?e2e`（`&fast` で最初の2ユニットだけ）。専用の保存先 `.e2e` を使う。`file://` で制限されたら `python -m http.server 8766` → `http://localhost:8766/fe.html?e2e`。
- manda・protesto・quien・futuro：`<アプリ>.html?sandbox` を開き、コンソールで `tests/e2e-<アプリ>.js` を script として読み込み、`await mandaE2E(['L1'])` のように呼ぶ（引数・ほかの関数は各ファイルの頭コメント）。モル教室は `mole.html?e2e`。
- 重なり：スマホの実際の高さ（375×550〜660）で開き、`tests/overlap.js` を読み込んで `overlaps()`。わざと重ねる所は `data-overlay-ok`。

## 動作確認
- `?sandbox`（別の保存先。本物の記録に触れない）。単語アプリ（vocab.html）は `?debug` も使う。
- **機種に依存しない**：使うのは iPhone の Safari と Android の Chrome。機種ごとの対策は標準の動きに上乗せする形だけ。
- iPhone で使える高さは 550〜660px。音と読み上げは、タップの中でないと iPhone では出ない。

## 公開・記録
- ファイルを直したら、入口 html の `?v=` を上げる。コースは `courses/<id>/course.js` の `version`。
- 区切りごとに commit して main へ push。

## 理由づけを書くとき（docs・コメント・お知らせ）
- 「〜は残りやすい」「〜すると定着する」と書く前に [根拠/README.md](根拠/README.md) を見て、出典番号（L○＝学習理論、G○＝ゲーム。[出典一覧](根拠/出典一覧.md)）を付ける。なければ〔経験則〕（依頼者の指摘）〔推論〕〔未確認〕と書く。優先は 出典 ＞ 経験則 ＞ 推論。
- 報告にない主張を「出典あり」と書かない。「抄録で確認」「検索要約のみ」「企業の報告」の区別はそのまま引きつぐ。
