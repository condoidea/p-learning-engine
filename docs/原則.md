# 原則（毎回読む短い版）

番号はユーザーの指摘を得た順。きっかけ・例は [原則-くわしく.md](原則-くわしく.md) にある（迷ったらそこで該当番号を見る）。

## 順番と分かりやすさ
1. **知識を入れる前に問題を出さない。** まず覚える（短く・楽しく）→ すぐ思い出す → 定着
2. **「タップするだけで解ける」問題は NG。** その知識を使わないと解けない操作にする
3. **受け身の「次へ」「次へ」にしない。** 自分で押す → 結果が出る。説明は「小さな問い（予想）→ 答えると説明」
22. **飛ばして置いていくほうが、長くてだるいよりまずい。** 書いたら全レッスンを頭から読み、未習の言葉・一段飛ばしを洗い出す。長くなるなら分ける。読み方を一度教えたら新しい名前も同じ読み方で解かせる
21. **説明は見る順に：見る → 根拠 → 結論 → 名前。** 結論や未習の言葉を先に出さない。図のキャプションでも答えを先に見せない
15. **説明を一足飛びにしない。** 1段の省略、書き方の約束、前提の関係は使う前に教える。長い所は「🤔 なぜ？」(`more`) で開く
19. **理由は「A だから B、B だから C」と途中を省略しない。** 言葉だけで分かりにくい所は図もそえる
16. **良い tips ほど理由（`why`）もそえる。** 問題で使うコツは、カードだけでなくレッスンで教える

## 目線と動き
20. **操作中は目線が操作の場所にある。** 書き換わる指示は、指示そのものの動き（`Y.chg`）で引く。別の場所への知らせ（トースト・バルーン）は NG。いちばん見せたいものを1つに決め、動きはそこだけ。次に触る物の目印は動かない光で静かに
4. **図形のアニメーションは説明に沿って、適度に。** 文章と図を連動させる
17. **言葉の説明より、前に動かした図をもう一度。** 前のウィジェットを新しいミッションで再登場させる

## 覚える・思い出す
14. **思い出させるときは手がかりを見せる。** 「問い（見える）＋答え（ぼかす）」。全部ぼかさない
5. **前に教えたことがまた出たら、同じ説明を復習として繰り返す。** 1〜2回で十分
23. **一度読んだだけでは全部は覚えられない前提。** まちがえた問題をレッスンごとに記録 → その場で Tips・表を開ける／要点だけの「おさらい」＋まちがえた問題へのリベンジ（正解で記録から消える）／ホームで次のレッスンより先に出す
18. **計算問題は「解き方の型」＋「数字が変わる演習」で厚く。** レッスンは軽いまま、`tip` と `drill`。まちがえたら1手ずつ

## 見た目・伝え方
7. **図がないと解けない画面を作らない。** 記号を使う問題には必ず図
8. **何をすれば合格か、いつも見えるように。** ミッションは具体的に、進み具合（●●○）も
9. **飾りが学習の邪魔をしたら本末転倒。** 文字の画面の背景は十分に暗く、色の太線や光は描かない
10. 操作の「ここちよさ」：指に遅れない・吸いつきは少し弾む・数字は足し算が合うように
11. **画面のポイントが一目で分かるように。** 文字は一文字ずつ流し、キーワードは跳ねてマーカー（`typewriter`）
12. **迷いそうな言葉にはこまめにヘルプ。** 本文に出たら自動で「？」（`autoGloss`）
13. **覚えること／覚え方／呼び方を見た目で分ける。** `**…**`＝覚えること、`__…__`＝覚え方（💡）、`((…))`＝便宜上の呼び方（📎）。最初のレッスンで教える。数式は囲まない

## 範囲
6. **教材の範囲・分量は元の資料に合わせる。** 盛りすぎない。ただし元の資料を見ないと分からない書き方（「プリントの図のとおり」）はしない
24. **「このアプリ全体をやれば、その試験のその分野が解けるレベルまで育てる」気合で範囲を決める。** 過去問の形をすべて洗い出して足し、試験と同じ形の問題と模試（分野別結果・弱点のおさらい・合格ライン）を置く。**範囲は公式の出題範囲で確かめる。記憶で「○級で習う」と書かない**

## 点検のしかた
完成前に全レッスンを通して、①説明より先に問題が出ていないか ②受け身の「次へ」が続いていないか ③図がないと解けない画面がないか ④資料より盛りすぎていないか ⑤太字が「覚えること」だけか、を見る。指摘された箇所だけでなく全体を直す。

## 太字の点検のしかた
「まとめ」と用語カードに出てこない太字を機械的に洗い出し、1つずつ「覚える／ヒント／呼び方／ただの強調」に振り分ける。計算問題の問題文の太字は外す。
